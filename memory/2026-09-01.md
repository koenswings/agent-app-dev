## Bug fixes shipped (2026-09-01)

### intakeReadyAt fix (v1.1.46)
- **Bug:** `intakeReadyAt` returned binary-search result even when baby was underfed (smoothed < D). At 15:00, smoothed=1188.9 vs D=1210.5 — underfed. The function correctly returned "now" per the new fix.
- **Fix:** Return `now` whenever `currentSmoothed < dailyTargetMl - TOLERANCE`. Only binary-search when genuinely overfed (smoothed ≥ D).
- Synced to milkwise RN as well.

### Timeline ghost markers feature (v1.1.47 → v1.1.51)

New design: timeline shows full sequence of all bottle sizes as ghost markers (gray, "earliest time this size shows 100% after last feed") + advised green marker at now + future markers in rose/teal.

**Multiple bugs fixed during rollout:**

| Version | Bug |
|---------|-----|
| v1.1.47 | Ghost readyAt computed from `now` instead of `lastFeed.timestamp` — all collapsed on "now" line |
| v1.1.48 | Fixed reference time (lastFeed.timestamp) |
| v1.1.49 | Wrong threshold: `D - milkMl` → `D * 1.005 - milkMl - 0.1` (Math.round boundary) |
| v1.1.50 | Binary search returned midpoint (could be 101% zone) → fixed to return `hi` |
| v1.1.51 | `hi` was e.g. 17:07:45 → displayed as 17:07 which is still 101%. Fixed with `Math.ceil(hi / 60_000) * 60_000` |

**Key lesson:** Ghost marker correctness requires three things: (1) reference time = lastFeed.timestamp, (2) threshold = D×1.005 - milk - 0.1 (not D - milk), (3) result ceiled to full minute.

## §8.7 analysis correction

Initial analysis was wrong. The case was NOT "bottle can't reach 100% at all" — it was "bottle overshoots because of the smoothed model plateau." The smoothed function has a floor at 1080ml from ~17:09 onward (old feeds fully credited, no more decay). At 15:00, smoothed=1188.9 < D=1210.5 so baby IS underfed, but the binary search was chasing `targetBefore = D - 135 = 1075.5` which is below the floor — hence returning 48h cap (18:15). Fix was to return `now` when underfed, not chase targetBefore.
