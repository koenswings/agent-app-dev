## Test Harness (app-harness)

### Repo: koenswings/app-harness
### Local: apps/app-harness/

### How it works
1. Checks no production IDEA App containers running (aborts if so)
2. Creates workdir with config.yaml + copied store-url.txt from engine
3. Symlinks fixture to /disks/sdb1
4. Spawns engine in testMode on port 18800, IDEA_MDNS_DISABLE=true, IDEA_WATCH_DIR=/dev/engine-test
5. Waits 18s for USB monitor to initialize
6. Touches /dev/engine-test/sdb1 → engine processes fixture disk
7. Polls docker ps until container shows Up, then polls HTTP readiness
8. Runs smoke tests against http://127.0.0.1:13334
9. Removes sentinel → engine undocks → container stopped
10. Kills engine, cleans up

### Full harness env
```
ENGINE_BIN=/home/pi/projects/engine/dist/src/index.js
ENGINE_MODULES=/home/pi/projects/engine/node_modules
ENGINE_CWD=/home/pi/projects/engine
ENGINE_PORT=18800
IDEA_WATCH_DIR=/dev/engine-test
IDEA_MDNS_DISABLE=true
IDEA_TEST_MODE=true
IDEA_SYSTEM_DISK_SKIP=true
STORE_DIR=/tmp/kit-test-store-$$
```

### Smoke test results
17/17 passing on idea02. Tests: HTTP 200 on all pages, /api/feeds returns array, /api/settings has required fields, POST feed persists, all 5 pages return 200.

### Known issue
Automerge store-watch (Axle's recommendation) fails on ARM due to WASM init. Documented in harness.mjs. Using docker ps + HTTP readiness poll instead. Flagged to Axle.

### Running tests
```bash
# On idea02 — stop production first
cd /instances/milkwise-idea02-001 && sudo docker compose down
# Then run
cd /home/pi/kit-test/app-harness
ENGINE_BIN=... ENGINE_CWD=... ENGINE_PORT=18800 IDEA_WATCH_DIR=/dev/engine-test STORE_DIR=/tmp/kit-test-store-$$ node tests/app-milkwise/smoke.mjs
# Restart production after
cd /instances/milkwise-idea02-001 && sudo docker compose up -d
```
