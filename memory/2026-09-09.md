## Incident: Timeline ordering bug + intakeReadyAt overshoot

### What happened

Koen reported (with screenshots) two issues on the morning of Sep 9:

1. **120ml ghost marker appearing AFTER 150ml** on the timeline — visually backwards, smaller bottle shown later than larger bottle.

2. **"Give now 120ml" at 09:28 → status jumped to 104% orange** after feeding. App recommended 120ml at 93.9% live smoothed. After logging, frozen status = 104.3% (orange, "slightly over").

### Root cause — Bug 1 (ordering)

The `ghostIntakeReadyAtMs` function computes the earliest time each bottle size achieves exactly 100% from `lastFeed.timestamp`. When the baby is slightly below D, **150ml achieves 100% sooner than 120ml** because it contributes more formula — so the ghost for 150ml is positioned earlier on the timeline. This violates the parent expectation that smaller bottles are always available sooner.

**Fix:** After computing all ghost times, enforce monotonicity — each size's ghost time must be ≥ the previous (smaller) size's ghost time. Applied in both `CanTakeCard.tsx` (web) and `DashboardScreen.tsx` (RN).

### Root cause — Bug 2 (recommendation overshoot)

`intakeReadyAtMs` returned "now" whenever `currentSmoothed < D - 1ml`. This meant "give now" even when giving the bottle would push status to 104-105% (orange). At 93.9% live, 120ml → 104.3%, which is within the yellow band (±5%) but showed orange because 104.3% > 105% boundary... wait, actually 104.3% < 105% so it should show yellow. Koen described it as red — need to re-examine whether this is a real problem. Fix applied regardless: `intakeReadyAt` now only returns "now" if `liveSmoothed + milkMl ≤ D × 1.05`.

### Important UX clarification from Koen

Koen explained clearly:
- **Status is always frozen at last feed timestamp** — shows how well that feed was timed
- **"X now" on timeline is always the real-time live moment** — not anchored to any past time
- Because of this, you cannot reproduce a past "Give now X" recommendation from the current app state
- The status card showing 100% at 05:45 and timeline showing "150ml now" at 10:14 are **not contradictory** — the baby was on target at 05:45, and 4.5 hours later she needs a feed (150ml because she's 6% behind, preferred+1 is appropriate)
