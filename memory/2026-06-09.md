## Predictor 3 — T* (binary search, deployed)

**Design doc:** `design/milkwise/next-session-predictor-design.md`

### Formula
Find T* such that `smoothed(T*) + milkPerBottle = dailyTargetMl`

```
target_before_feed = dailyTargetMl − milkPerBottle

if smoothed(lastFeed) ≤ target_before_feed:  T* = lastFeed  (give now, underfed)
elif smoothed(T_max) > target_before_feed:   T* = T_max     (still overfed at cap)
else: binary search T* in [lastFeed, T_max], ~30 iterations, 1-min precision
```

**Guarantee:** giving milkPerBottle at T* produces smoothed = dailyTargetMl exactly (unless cap applies).

**Settings flag:** `useTargetAwarePredictor` (default `true`). `false` = Predictor 2 (Formula S).

### Why Predictor 2 (Formula S) was insufficient
Formula S: `adjustedNext = standard + surplus/hourlyRate (capped)`
This doesn't account for feeds crossing the 24h boundary before the next feed.
In the 09:01 → 11:53 example:
- Predictor 2 suggested 11:12 (−17min correction based on −11.28ml surplus)
- Predictor 3 gives 10:56 (binary search finds exact T* where smoothed = 870.5ml)
- Actual result at 11:53: smoothed jumped to 970ml (boundary crossing of 08:45 feed shed 89.22ml, new feed added 100ml)

### Display principle (non-negotiable)
`smoothedAt = lastFeed.timestamp` always. Status frozen at last feed. Only `now` ticks for relative time labels.
